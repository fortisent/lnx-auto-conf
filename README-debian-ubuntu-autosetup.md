# Интерактивная автонастройка Debian и Ubuntu

`debian-ubuntu-autosetup.sh` — консервативный интерактивный Bash-скрипт для первичной настройки сервера. Он показывает опасные действия заранее, сохраняет изменяемые конфигурации и проверяет результат каждого защитного этапа.

## Поддерживаемые версии

Матрица проверена для актуальных поддерживаемых релизов на август 2026 года:

- Debian 13 `trixie` — stable;
- Debian 12 `bookworm` — LTS до 30 июня 2028 года;
- Ubuntu 26.04 LTS `resolute`;
- Ubuntu 24.04 LTS `noble`;
- Ubuntu 22.04 LTS `jammy`.

На другой версии скрипт остановится. Флаг `--allow-unsupported` снимает только эту блокировку и не гарантирует совместимость. Скрипт никогда не выполняет переход между версиями дистрибутива.

## Что настраивается

1. Проверка ОС, версии, root, systemd, контейнера, SSH-сессии и cloud-init.
2. Необязательный APT-прокси, учитываемый последующей проверкой HTTPS.
3. Аудит сети и проверка маршрута, DNS и HTTPS.
4. DHCP или статический IPv4 через уже активный Netplan, NetworkManager, systemd-networkd или простой ifupdown.
5. Нормализация официальных APT-источников в Deb822 и HTTPS; сторонние репозитории сохраняются.
6. `apt update`, обычный `upgrade` либо отдельно подтверждаемый `full-upgrade`.
7. Установка SSH, sudo, UFW, Fail2ban, ClamAV и диагностических инструментов.
8. Создание пользователя, добавление в группу `sudo`, пароль и публичный SSH-ключ.
9. SSH drop-in с проверкой `sshd -t`, reload и проверкой прослушиваемого порта.
10. UFW с deny incoming, allow outgoing и предварительным разрешением SSH.
11. Fail2ban для SSH; экспериментальный jail по журналу UFW выключен по умолчанию.
12. ClamAV: ручной режим, безопасное еженедельное сканирование либо daemon.
13. Автоматические обновления безопасности через системные APT-таймеры.
14. Необязательная подготовка миграции сети на Netplan или NetworkManager.
15. Итоговые проверки служб, firewall, связности и необходимости перезагрузки.

## Первый запуск

Сначала скопируйте оба файла на сервер и выполните только аудит:

```bash
chmod 700 debian-ubuntu-autosetup.sh
sudo ./debian-ubuntu-autosetup.sh --audit-only
```

Затем посмотрите план команд без применения изменений:

```bash
sudo ./debian-ubuntu-autosetup.sh --dry-run
```

Для реальной настройки:

```bash
sudo ./debian-ubuntu-autosetup.sh
```

Справка:

```bash
./debian-ubuntu-autosetup.sh --help
```

## Безопасность и восстановление

- Запускайте первый реальный прогон из консоли гипервизора, IPMI/KVM либо имея snapshot виртуальной машины.
- Не закрывайте текущую SSH-сессию, пока вход по ключу и новый порт не проверены во второй сессии.
- Netplan применяется через `netplan try` с 90-секундным откатом. У NetworkManager и ifupdown такого универсального отката нет, поэтому требуется дополнительное подтверждение.
- При наличии cloud-init проверьте его сетевые и SSH-настройки: cloud-init может восстановить собственную конфигурацию после перезагрузки.
- Сложные VLAN, bridge, bond, VRF, policy routing и несколько default route скрипт намеренно не мигрирует автоматически.
- Старые правила UFW для порта 22 не удаляются автоматически после смены SSH-порта.
- ClamAV только сообщает о найденных объектах. Автоматическое удаление и карантин не включаются.
- Пароли пользователя вводятся штатной командой `passwd` и не пишутся в журнал. URL прокси с паролем сохраняется в root-only APT-файле — по возможности используйте прокси без встроенных учётных данных.

Перед изменением файла или каталога создаётся копия в:

```text
/var/backups/debian-ubuntu-autosetup/YYYYMMDD-HHMMSS/
```

Структура каталогов внутри копии повторяет корневую файловую систему. Восстанавливайте только нужные файлы и предварительно проверяйте их содержимое; автоматический массовый rollback намеренно не выполняется.

Журналы реального запуска:

```text
/var/log/debian-ubuntu-autosetup/run-YYYYMMDD-HHMMSS.log
```

Журнал имеет права `0600`. В режиме `--dry-run` он создаётся в `/tmp`.

## Репозитории

Для Debian создаётся `/etc/apt/sources.list.d/debian.sources`, для Ubuntu — `/etc/apt/sources.list.d/ubuntu.sources`. Официальные старые записи отключаются, но сохраняются в резервной копии. `deb-src`, Debian `contrib/non-free` и Ubuntu backports включаются только по запросу.

На Ubuntu для `amd64/i386` используются `archive.ubuntu.com` и `security.ubuntu.com`; для портовых архитектур — `ports.ubuntu.com`. Архивные keyring-файлы указываются через `Signed-By`.

## Ограничения

- Скрипт рассчитан на обычную систему с Bash, APT и systemd. В контейнере сеть и UFW пропускаются.
- Изменение существующего сложного stanza ifupdown не выполняется автоматически.
- Подготовка нового сетевого backend не доказывает, что старый перестал управлять интерфейсом. Это нужно проверить до перезагрузки.
- Экспериментальная блокировка «сканирования портов» реагирует только на частые записи `[UFW BLOCK]`; она не заменяет IDS/IPS и может давать ложные срабатывания.
- Настройки сторонних репозиториев, приложений, VPN, policy routing и облачного firewall находятся вне области скрипта.

## Проверка после запуска

Минимально проверьте:

```bash
sshd -t
ss -ltn
ufw status verbose
fail2ban-client status sshd
systemctl --failed
apt-get update
```

Если существует `/var/run/reboot-required`, запланируйте контролируемую перезагрузку и снова проверьте сеть, SSH, UFW и Fail2ban.
